# Specification

## Requirements

Reframe — приватный голосовой КПТ-дневник для профессионалов под стрессом. Пользователь описывает тревожащую ситуацию голосом, приложение анализирует её через призму когнитивно-поведенческой терапии (Бёрнс) и предлагает рефрейминг — нейтральный взгляд стороннего наблюдателя.

## Основной пользовательский сценарий

### 1. Главный экран и оценка тревоги
- В верхней части экрана — заголовок «Reframe» и подзаголовок «голосовой КПТ-дневник» в стиле дизайн-системы.
- Навигация: TabBar с иконками и подписями (Главная, История, Прогресс).
- При наведении на иконку — tooltip с названием раздела.
- Активная вкладка подсвечена янтарным цветом.
- При открытии приложения пользователь видит главный экран с большой кнопкой «Говорить» и ползунком уровня тревоги (шкала 1–10).
- Якоря на ползунке: 1 — «спокойно», 5 — «тревожно», 10 — «предельно».
- При наведении (tooltip) — описания всех 10 уровней по шкале SUDS.
- До начала сессии пользователь оценивает текущий уровень тревоги (pre-session rating).
- Под кнопкой «Говорить» — случайная тема-подсказка из библиотеки 10-15 тем.
- Темы сгруппированы по категориям: работа, отношения, здоровье, самооценка, будущее.
- Тема меняется при каждом открытии приложения и после завершения сессии.
- При уровне тревоги 9-10 — рядом со слайдером появляется кнопка «Помощь».
- Кнопка открывает дыхательное упражнение: цикл 4с вдох / 4с задержка / 4с выдох.
- Анимированный круг, меняющий размер на каждом этапе. 3 цикла.
- Интерфейс: дизайн-система v2 (navy/amber, центральная композиция), тёмная тема по умолчанию, зоны касания ≥48px.

### 2. Голосовой ввод
- Пользователь нажимает кнопку «Говорить» — запускается запись через Web Speech API (браузерный распознаватель речи).
- Длительность записи: до 3 минут. Запись останавливается автоматически по истечении времени или вручную по кнопке «Стоп».
- Во время записи отображается визуальная обратная связь (индикатор записи, осциллограмма или пульсирующая иконка).
- Браузеры без поддержки Web Speech API: вместо кнопки «Говорить» — текстовое поле ввода и кнопка «Отправить». Пользователь пишет текст вручную. Весь остальной флоу (анализ, рефрейминг, оценка, сохранение) — без изменений.
- Во время записи доступна кнопка «Отмена» — запись прерывается, сессия не сохраняется.
- Если пользователь оценил тревогу, но не завершил запись — оценка не сохраняется.
- Если распознавание не дало текста (тишина, неразборчивая речь, шум): показать сообщение «Не удалось распознать речь. Попробуйте ещё раз.» и кнопку «Записать заново».
- Во время записи отображается распознаваемый текст в реальном времени (interim results из Web Speech API).
- После остановки записи пользователь видит итоговый текст перед отправкой.
- После остановки записи — итоговый текст показывается пользователю для проверки (только для голосового ввода).
- При текстовом вводе — текст отправляется сразу, без этапа проверки.
- Кнопка «Отправить» отправляет текст на анализ. Кнопка «Записать заново» возвращает к записи.

### 3. Отправка и анализ
- После проверки текста пользователем кнопка «Отправить» отправляет распознанный текст на бэкенд.
- Бэкенд — тонкий прокси: форматирует системный промпт (анализ когнитивных искажений + рефрейминг), передаёт в LLM, возвращает ответ LLM на фронтенд.
- Бэкенд не сохраняет текст, не имеет базы данных, не логирует содержимое записей.
- На бэкенде должен быть rate limiting для предотвращения спама.

### 4. Отображение результата
Пользователь видит ответ LLM, содержащий:

**a) Когнитивное искажение** — классификация по одному из типов:
- Катастрофизация (catastrophizing)
- Персонализация (personalization)
- Чтение мыслей (mind reading)
- Предсказание будущего (fortune telling)
- Чёрно-белое мышление (black-and-white thinking)
- Сверхобобщение (overgeneralization)
- Эмоциональное обоснование (emotional reasoning)
- Долженствование (should statements)
- Навешивание ярлыков (labeling)
- Фильтрация (mental filter / disqualifying the positive)

- Рядом с каждым типом искажения — иконка ℹ️.
- При клике — краткое объяснение искажения с примером.
- Внизу результатов — ссылка «Узнать больше об искажениях» → справочный экран со всеми 10 типами.

**b) Рефрейминг** — короткий текст (до 50 слов) в формате стороннего наблюдателя: без оценки, без банальных советов, только факты. Системный промпт требует переформулировать мысль нейтрально, избегая токсичного позитива.
- Для каждого найденного искажения показывается: цитата из речи пользователя → тип искажения → рациональный контраргумент.
- Рефрейминг дополняется техникой трёх колонок: автоматическая мысль → когнитивное искажение → рациональный ответ.
- В конце сессии — закрепляющий вопрос (сократический диалог).

### 4b. Техника «Вертикальная стрелка» (Vertical Arrow)

После получения рефрейминга пользователь может опционально углубить анализ:

- Под результатом — кнопка «Копнуть глубже».
- При нажатии — предложение записать, что эта мысль говорит о пользователе.
- Пользователь говорит (одно предложение).
- LLM анализирует через Vertical Arrow (Бёрнс): поверхностная мысль → промежуточная → глубинное убеждение.
- Результат — визуальная «лестница»:
  ```
  «Я опоздал»
     ↓
  «Я безответственный»
     ↓
  «Я недостаточно хорош»
  ```
- Каждая ступень подписана: «Поверхностная мысль», «Промежуточная», «Глубинное убеждение».
- Ниже — рефрейминг глубинного убеждения.
- Оценка тревоги — одна, в конце всей сессии (как и раньше).
- Vertical Arrow — опциональный шаг. Пользователь может пропустить и сразу сохранить.

### 4c. Микро-взаимодействия и tone of voice

#### Анимации и переходы
- Все переходы между фазами — плавные (fade-in 0.3s).
- Фаза «Анализирую...» — медитативная анимация (три пульсирующие точки или спокойный спиннер).
- Появление результата — последовательный fade-in: искажения → рефрейминг → вопрос.
- Сохранение сессии — микро-анимация подтверждения (checkmark).

#### Tone of voice
- Все сообщения — эмпатичные, без технического жаргона.
- «Не удалось распознать речь» → «Не расслышал. Попробуем ещё раз?»
- «Анализирую...» → «Смотрю на ситуацию...»
- «Ошибка сети» → «Кажется, нет связи. Проверим?»
- «Говорите...» → «Я слушаю...»
- Пустые состояния — тёплые, поддерживающие.

### 5. Оценка после сессии
- После получения ответа пользователь повторно оценивает уровень тревоги (post-session rating) на том же ползунке 1–10.
- Отображается разница (дельта) между оценками «до» и «после».

### 6. Сохранение сессии
Сессия сохраняется в localStorage. Состав записи:
- Дата и время
- Тип выявленного когнитивного искажения
- Уровень тревоги «до» (1–10)
- Уровень тревоги «после» (1–10)
- Дельта (разница)
- ✅ Все найденные искажения сохраняются (массив, до 4 шт.)
- ✅ Результат Vertical Arrow сохраняется (уровни + рефрейминг), если был сделан
- ✅ Текст рефрейминга сохраняется в сессии (≤ 50 слов, обезличенная переформулировка)
- В списке истории показывается только дата, искажение, дельта
- При клике на сессию — детали: искажение, рефрейминг, оценки до/после, дельта, Vertical Arrow (если есть)
- Расшифровка голоса НЕ сохраняется (приватность)

### 7. Обработка ошибок

#### Сетевые ошибки
- Нет соединения: ErrorBanner «Ошибка сети. Проверьте подключение.» + кнопка «Повторить».
- HTTP 502/500 (LLM недоступен): ErrorBanner «Не удалось получить ответ. Попробуйте через минуту.» + кнопка «Повторить».
- HTTP 429 (rate limit): ErrorBanner с эмпатичным сообщением и таймером обратного отсчёта. Время ожидания берётся из заголовка Retry-After ответа бэкенда. Без кнопки повтора — кнопка появляется автоматически после истечения таймера.

#### Ошибки ответа LLM
- Таймаут (504): ErrorBanner «Не удалось получить ответ. Попробуйте через минуту.» + кнопка «Повторить».
- Обрыв ответа на полуслове: показана полученная часть + предупреждение «Ответ получен не полностью.»
- Неожиданная структура (нет distortion/reframing): ErrorBanner + кнопка «Повторить».

#### Ошибки распознавания речи
- Пустой текст после записи (тишина/шум): сообщение «Не удалось распознать речь. Попробуйте ещё раз.» + возврат к началу записи.
- Ошибка API распознавания (no-speech, audio-capture): сообщение «Не удалось распознать речь. Попробуйте ещё раз.»
- Браузер без Web Speech API: заглушка «Голосовой ввод доступен в Chrome. Откройте приложение в Chrome, чтобы начать.»

#### Ошибки валидации (бэкенд)
- Пустой текст (400): сообщение «Текст не может быть пустым.»
- Текст >3000 символов (400): обрезка до лимита на клиенте.
- Неверный метод (405): не показывается пользователю (обрабатывается на уровне API).
- Неподдерживаемый Content-Type (415): не показывается пользователю.

#### Поведение при ошибках
- При любой ошибке состояние сессии сохраняется. Кнопка «Повторить» переотправляет тот же текст.
- При ошибке после Vertical Arrow — возврат к результату первого раунда (не к началу).

### 7b. Операционное логирование (бэкенд)

Для диагностики ошибок LLM бэкенд должен вести операционные логи:

- Логирование ошибок LLM (таймауты, ошибки API, превышение retry) — с типом ошибки и контекстом, но БЕЗ текста пользователя, промптов и ответов LLM.
- Логирование retry-попыток: номер попытки, задержка, результат.
- Логирование старта и конфигурации сервера (порт, режим mock/real).
- **Запрещено**: логирование пользовательского текста, промптов, ответов LLM (конституция §I).
- Ротация логов: ежедневные файлы `logs/reframe.YYYY-MM-DD.log`, автоочистка старше 7 дней.
- Два уровня вывода: консоль (INFO+) для docker/systemd, файл (DEBUG+) для диагностики.
- Уровни логирования:
  - `DEBUG` — вызов LLM, время ответа, режим (mock/real)
  - `INFO` — старт сервера, успешный retry
  - `WARN` — retry-попытка, rate limit
  - `ERROR` — исчерпание retry, таймаут, ошибка API (со stack trace)

### 7c. Клиентское логирование (фронтенд)

Для диагностики ошибок на стороне браузера фронтенд пишет в `console.warn` / `console.error`:

- Все ошибки HTTP (non-2xx) — статус, URL, тип ошибки (без текста пользователя).
- Таймауты и обрывы соединения — тип ошибки (TimeoutError, AbortError, TypeError).
- Ошибки парсинга ответа SSE — факт ошибки, без содержимого.
- Предупреждения о частичных ответах — факт неполноты.
- **Запрещено**: логирование текста пользователя, промптов, ответов LLM.
- Логи — только в консоль браузера, никуда не отправляются (приватность).

## Дополнительные экраны

### 8. Вкладка «История»
- Список всех сессий: дата, время, тег когнитивного искажения.
- Без текста записей и рефрейминга — только метаданные.
- Возможность увидеть детали конкретной сессии: искажение, рефрейминг, дельту тревоги (текст сессии при этом не раскрывается).
- Если сессий нет: пустое состояние с тёплым текстом. Вкладка видна и кликабельна.

### 9. Вкладка «Прогресс»
- Сводка в виде карточек: общее количество сессий, средняя дельта тревоги.
- Тренд: стрелка вверх/вниз с текстом «Тревога снижается» или «Тревога растёт» на основе сравнения первой и последней сессии.
- Облако тегов: самые частые когнитивные искажения, размер шрифта пропорционален частоте.
- Если сессий нет — заглушка «Твой прогресс появится здесь после первых сессий».

### Первый запуск
- Многошаговый онбординг в стиле Calm: 4 шага с кнопкой «Далее», финальный шаг — «Начать».
- Шаги: приветствие → как работает → рефрейминг → приватность.
- После прохождения флаг в localStorage, больше не показывается.
- Tone of voice приложения — спокойный, профессиональный. Обращение на «Вы». Примеры:
  - «Добро пожаловать в Reframe. Приватный дневник для работы с тревожными мыслями.»
  - «Расскажите, что вас тревожит — приложение слушает и анализирует ваши мысли.»
  - «Ваши записи не покидают это устройство. Никаких серверов, никакой телеметрии.»

### Производительность
Требования к производительности — согласно конституции, раздел «Требования к производительности».

### Системный промпт
- Промпт для LLM формулирует задачу как «нейтральный наблюдатель»: никаких банальных советов («всё будет хорошо», «не переживайте»), только переформулировка ситуации с опорой на факты.
- Промпт требует определить конкретный тип когнитивного искажения из заданного списка.
- Рефрейминг строго ≤ 50 слов.
- Конкретный текст промпта и примеры — в плане реализации (plan.md). Здесь зафиксированы только требования к результату.

## User Stories

Как профессионал в стрессе, я хочу рассказать о том, что меня тревожит, и получить нейтральный, переосмысленный взгляд на ситуацию.

Как пользователь, ценящий приватность, я хочу чтобы все мои данные оставались на устройстве — без страха что мысли будут храниться где-то ещё.

Как пользователь, следящий за ментальным здоровьем, я хочу видеть уровень тревоги до и после сессии и отслеживать прогресс.

Как мобильный пользователь, я хочу чтобы интерфейс работал на телефоне — чтобы вести дневник где угодно.

Как новый пользователь, я хочу краткое введение чтобы начать пользоваться сразу.

## v2 — Multi-Agent платформа

> Статус: v2.0–v2.2. v1 стабилен на `/`. v2 — «линза» на `/studio` (не заменяет дневник).

### Решения (зафиксированы)

| Вопрос | Решение |
|--------|---------|
| Позиционирование | **Coexist**: v1 = КПТ-дневник на `/`; v2 = «линза» на `/studio`. Дневник не умирает. |
| Взрывная ценность | **Демо-контраст**: одна ситуация → Бёрнс + Стоик → один вывод «Что унести». |
| Результат (иерархия) | **Hero = «Что унести»**; линзы ниже; Quiet UI (минимум chrome). |
| Follow-up | **Один ход** после takeaway (вопрос → ответ → обновлённый вывод). Не open chat, не multi-session. |
| SSE | **Agent-complete**; follow-up — одно SSE-событие consensus. |
| Burns payload | Structured JSON; в UI: reframing главный; искажения/question под «ещё» (свёрнуто). |
| Persistence | **Нет** в v2.x — studio не пишет в историю/прогресс. |
| Dig deeper (VA staircase) | **Отложено** (отдельный трек; не путать с studio-followup). |
| Folder migration | **Нет** — только `components/v2/`. |

### Концепция

Пользователь описывает **одну конкретную ситуацию**. N AI-агентов анализируют её параллельно. Progressive карточки линз; итог — синтез «Что унести» (если ≥2 успешных ответа). Архитектура расширяема: новый агент = запись в реестре + промпт.

### Discovery

На главном экране v1 (`/`) — ссылка «Два взгляда на ситуацию →» → `/studio`. Без TabBar-вкладки. На `/studio` — возврат «К дневнику».

### Агенты (v2.0)

| ID | Имя | Роль | Модель (дефолт) | Thinking | Формат ответа |
|----|-----|------|-----------------|----------|---------------|
| `:burns` | Д-р Бёрнс | КПТ: искажения + рефрейминг | `deepseek-v4-flash` | disabled | structured JSON (как v1) |
| `:stoic` | Стоик | Контролируемое vs нет | `deepseek-v4-flash` | disabled | `{ "text": "..." }` |
| `:consensus` | (синтез) | Что унести с двух взглядов | `deepseek-v4-flash` | **enabled** (reasoner-режим) | `{ "text": "..." }` |

v1 (`POST /api/reframe` без `:agents`) использует `LLM_MODEL` (дефолт `deepseek-v4-flash`) с `LLM_THINKING=disabled` — стабильный JSON без CoT.

**DeepSeek V4**: актуальные ID — `deepseek-v4-flash` и `deepseek-v4-pro`. Legacy `deepseek-chat` / `deepseek-reasoner` сняты (июль 2026). Reasoning — параметр `thinking: {type: enabled|disabled}`, не отдельная модель. Per-agent override: `REFRAME_AGENT_BURNS` / `_STOIC` / `_CONSENSUS` (+ `*_THINKING`). Для качества consensus можно выставить `REFRAME_AGENT_CONSENSUS=deepseek-v4-pro`.

Будущие (не в v2.0): `:friend`, `:skeptic`, `:analyst`; Dig deeper; выбор агентов пользователем.

### CJM (v2.2 Quiet UI + один follow-up)

1. **Discovery**: «Два взгляда на ситуацию →»
2. **Ввод**: заголовок «Два взгляда»; пример только в placeholder; `InputMethod`
3. **Анализ**: SSE; hero «Собираю вывод…»; линзы progressive
4. **Вывод**: **Что унести** → линзы (роли мелкие; Burns details свёрнуты)
5. **Follow-up (один ход)**: вопрос (Burns `question` или fallback) → ответ / «Пропустить» → при ответе обновляется только hero → «Понял»

Копирайт:
- Discovery: `Два взгляда на ситуацию →`
- Title: `Два взгляда` (без подзаголовка)
- Placeholder: `Напр.: опоздал на созвон, молчат — кажется, злятся`
- Consensus: `Что унести`
- Follow-up fallback: `Что из этого важнее забрать с собой?`
- Role Burns / Stoic: как раньше, 11–12px
- CTA конец: `Понял`

API follow-up: `POST /api/reframe` с `mode: "studio-followup"`, поля `text`, `surface`, `takeaway`, `question` → одно SSE consensus-событие. Линзы не пересобираются.

### Partial failure

- Успешный агент → карточка с результатом
- Упавший агент → карточка со статусом ошибки (остальные видны)
- Консенсус вызывается только если успешных агентов ≥ 2; иначе hero скрыт
- Полный провал всех агентов → ErrorBanner + «Повторить»

### UI-компоненты

- `AgentCard` — имя + мелкая роль; Burns: reframing; details под «ещё»
- `ConsensusView` — hero «Что унести»
- `StudioScreen` — quiet input; результат → follow-up → «Понял»; «К дневнику» только в шапке
- Без бейджей модели; без open chat

### Что остаётся от v1

Голосовой ввод, текстовый фолбэк, тёмная тема, история, прогресс, rate limiting, Vertical Arrow, тревога. Роуты v1 без изменений.

### Что нового (v2.x)

Параллельная оркестрация, agent-complete SSE, Quiet UI, один studio-followup ход.
