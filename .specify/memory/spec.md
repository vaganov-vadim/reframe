# Specification

## Requirements

Reframe — приватный голосовой КПТ-дневник для профессионалов под стрессом. Пользователь описывает тревожащую ситуацию голосом, приложение анализирует её через призму когнитивно-поведенческой терапии (Бёрнс) и предлагает рефрейминг — нейтральный взгляд стороннего наблюдателя.

## Основной пользовательский сценарий

### 1. Главный экран и оценка тревоги
- При открытии приложения пользователь видит главный экран с большой кнопкой «Говорить» и ползунком уровня тревоги (шкала 1–10).
- Якоря на ползунке: 1 — «спокойно», 5 — «заметная тревога», 10 — «предельно тревожно».
- При наведении (tooltip) — описания всех 10 уровней по шкале SUDS.
- До начала сессии пользователь оценивает текущий уровень тревоги (pre-session rating).
- Интерфейс минималистичный: тёплая нейтральная палитра, тёмная тема по умолчанию, зоны касания ≥48px.

### 2. Голосовой ввод
- Пользователь нажимает кнопку «Говорить» — запускается запись через Web Speech API (браузерный распознаватель речи).
- Длительность записи: до 3 минут. Запись останавливается автоматически по истечении времени или вручную по кнопке «Стоп».
- Во время записи отображается визуальная обратная связь (индикатор записи, осциллограмма или пульсирующая иконка).
- Браузеры без поддержки Web Speech API: показывается заглушка «Голосовой ввод доступен в Chrome. Откройте приложение в Chrome, чтобы начать.»
- Во время записи доступна кнопка «Отмена» — запись прерывается, сессия не сохраняется.
- Если пользователь оценил тревогу, но не завершил запись — оценка не сохраняется.
- Если распознавание не дало текста (тишина, неразборчивая речь, шум): показать сообщение «Не удалось распознать речь. Попробуйте ещё раз.» и кнопку «Записать заново».

### 3. Отправка и анализ
- После остановки записи распознанный текст отправляется на бэкенд.
- Бэкенд — тонкий прокси: форматирует системный промпт (анализ когнитивных искажений + рефрейминг), передаёт в LLM, возвращает streaming-ответ на фронтенд.
- Бэкенд не сохраняет текст, не имеет базы данных, не логирует содержимое записей.
- На бэкенде должен быть rate limiting для предотвращения спама.

### 4. Отображение результата
Пользователь видит streaming-ответ, содержащий:

**a) Когнитивное искажение** — классификация по одному из типов:
- Катастрофизация (catastrophizing)
- Персонализация (personalization)
- Чтение мыслей (mind reading)
- Чёрно-белое мышление (black-and-white thinking)
- Сверхобобщение (overgeneralization)
- Эмоциональное обоснование (emotional reasoning)
- Долженствование (should statements)
- Навешивание ярлыков (labeling)
- Фильтрация (mental filter / disqualifying the positive)

**b) Рефрейминг** — короткий текст (до 50 слов) в формате стороннего наблюдателя: без оценки, без банальных советов, только факты. Системный промпт требует переформулировать мысль нейтрально, избегая токсичного позитива.

### 5. Оценка после сессии
- После получения ответа пользователь повторно оценивает уровень тревоги (post-session rating) на том же ползунке 1–10.
- Отображается разница (дельта) между оценками «до» и «после».

### 6. Сохранение сессии
Сессия сохраняется в localStorage. Состав записи:
- Дата и время
- Тип выявленного когнитивного искажения
- Уровень тревоги «до» (1–10)
- Уровень тревоги «после» (1–10)
- Дельта (разница)
- ✅ Текст рефрейминга сохраняется в сессии (≤ 50 слов, обезличенная переформулировка)
- В списке истории показывается только дата, искажение, дельта
- При клике на сессию — детали: искажение, рефрейминг, оценки до/после, дельта
- Расшифровка голоса НЕ сохраняется (приватность)

### 7. Обработка ошибок
- Ошибка LLM (500, таймаут): сообщение «Не удалось получить ответ. Попробуйте через минуту.» + кнопка «Повторить».
- Обрыв streaming на полуслове: показать полученную часть ответа + предупреждение «Ответ получен не полностью.»
- LLM вернул ответ неожиданной структуры (нет искажения/рефрейминга): показать общее сообщение + кнопка «Повторить».

## Дополнительные экраны

### 8. Вкладка «История»
- Список всех сессий: дата, время, тег когнитивного искажения.
- Без текста записей и рефрейминга — только метаданные.
- Возможность увидеть детали конкретной сессии: искажение, рефрейминг, дельту тревоги (текст сессии при этом не раскрывается).
- Если сессий нет: пустое состояние с тёплым текстом. Вкладка видна и кликабельна.

### 9. Вкладка «Прогресс»
- Линейный график изменения уровня тревоги за последние 7 дней.
- На графике: оценки «до» и «после» для каждой сессии, тренд.
- Если сессий за 7 дней нет — показать заглушку с мотивирующей фразой.

### Дизайн-система (v2)
После редизайна: центральная композиция, глубокая navy-палитра (Calm-inspired), янтарный акцент (Headspace-inspired). Кнопка записи — центральный элемент с breathing-анимацией. Минимальный TabBar с иконками без текста. Типографика: system-ui, 17px base, крупные заголовки, много воздуха.

### Первый запуск
- При первом открытии приложения показывается краткий оверлей с инструкцией:
  - Как работает приложение (говорите → получаете рефрейминг)
  - Как оценивать тревогу (шкала 1–10)
  - Что данные остаются только на устройстве
- Оверлей закрывается по кнопке «Понятно» и больше не показывается (флаг в localStorage).
- Tone of voice приложения — «друг, который выслушает и поддержит». Без императивов. Примеры:
  - Вместо «Начните сессию» → «Давай начнём. Это займёт пару минут.»
  - Вместо «Нет данных за 7 дней» → «Твой прогресс появится здесь после первых сессий.»

### Производительность
Требования к производительности — согласно конституции, раздел «Требования к производительности».

### Системный промпт
- Промпт для LLM формулирует задачу как «нейтральный наблюдатель»: никаких банальных советов («всё будет хорошо», «не переживайте»), только переформулировка ситуации с опорой на факты.
- Промпт требует определить конкретный тип когнитивного искажения из заданного списка.
- Рефрейминг строго ≤ 50 слов.
- Конкретный текст промпта и примеры — в плане реализации (plan.md). Здесь зафиксированы только требования к результату.

## User Stories

As a stressed professional, I want to speak about what's bothering me and get a neutral, reframed perspective so that I can distance myself from emotionally charged situations.

As a privacy-conscious user, I want all my data to stay on my device so that I can speak freely without fear of my thoughts being stored or analyzed elsewhere.

As a user tracking my mental health, I want to see my anxiety level before and after each session and view progress over time so that I can measure the effectiveness of the reframing technique.

As a mobile user, I want the interface to work well on my phone so that I can use the diary whenever stress hits, not just at my desk.

As a first-time user, I want a brief introduction to how the app works so that I can start using it immediately without confusion.
