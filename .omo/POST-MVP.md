# POST-MVP — Отложенные требования и ограничения v1

Осознанные ограничения первой версии. Будут пересмотрены после валидации MVP на реальных пользователях.

---

## 🔴 Критические (блокируют часть пользователей)

### Текстовый ввод как fallback
**Сейчас**: только голосовой ввод через Web Speech API.
**Проблема**: не работает в Firefox, Safari, некоторых mobile-браузерах.
**v2**: добавить текстовое поле ввода как альтернативу голосу. Пользователь выбирает способ ввода.

### Поддержка браузеров без Web Speech API
**Сейчас**: приложение требует Web Speech API.
**v2**: определить список поддерживаемых браузеров, показывать предупреждение в неподдерживаемых.

---

## 🟠 Важные (качество опыта)

### Обработка ошибок и деградация
**Сейчас**: базовые состояния загрузки.
**v2**:
- Понятные сообщения об ошибках на языке пользователя
- Retry при таймауте LLM
- Сохранение текста при обрыве соединения (не терять надиктованное)
- Индикатор прогресса между остановкой записи и первым токеном

### Замена localStorage
**Сейчас**: localStorage (5–10 MB лимит).
**v2**: IndexedDB — больше объём, структурированные запросы, транзакции.
**v3**: опциональный экспорт/импорт данных (JSON).

### Миграция данных
**Сейчас**: нет версионирования схемы.
**v2**: версионирование структуры сессий, автоматическая миграция при обновлении.

### Observability
**Сейчас**: нет.
**v2**:
- Структурированное логирование на бэкенде (только метаданные запросов, не содержимое)
- Метрики: latency до LLM, доля таймаутов, ошибки распознавания
- Alerting при деградации

### Нормализация текста
**Сейчас**: только trim + проверка пустоты + обрезка до 3000 символов.
**v2**: удаление шума распознавания (повторы, артефакты STT), опциональная нормализация без потери эмоционального контента.

## 🟡 Желательные (расширение аудитории)

### Accessibility (a11y)
**Сейчас**: не реализовано.
**v2**:
- Screen reader поддержка (ARIA-лейблы)
- Навигация с клавиатуры
- WCAG 2.1 Level AA

### Мульти-устройство / синхронизация
**Сейчас**: данные только на одном устройстве.
**v2**: исследовать безопасные способы синхронизации (e2e-encrypted, peer-to-peer) без нарушения принципа приватности.

### Тёмная тема как единственная
**Сейчас**: тёмная по умолчанию, светлая опционально.
**v2**: расследовать, нужна ли светлая тема вообще для целевой аудитории.

### Поведенческий эксперимент (Behavioural Experiment)

После сессии LLM предлагает конкретный эксперимент для проверки когнитивного искажения в реальности. Например: «Спроси у коллеги, заметил ли он опоздание. Запиши результат.»

**Пользовательский путь:**
1. В конце сессии LLM формулирует эксперимент
2. На следующий день — напоминание на главном экране: «🎯 Твой эксперимент: ...»
3. Кнопка «Рассказать результат» → голосовой ввод → мини-анализ
4. «Реальность: коллега не заметил. Искажение: чтение мыслей. Эксперимент подтвердил — твои страхи были преувеличены.»

**КПТ-ценность**: пользователь не просто рефлексирует, а проверяет гипотезы в реальном мире. Ядро методологии Бёрнса.

**Сложность**: требует хранения активного эксперимента в localStorage и UI-напоминания.

## 🔵 Технический долг и оптимизация

### Размер JS-бандла
**Сейчас**: без ограничения.
**v2**: бюджет ≤ 150 KB gzipped, анализ бандла, code splitting, ленивая загрузка графиков.

### Offline-режим
**Сейчас**: без сети приложение не работает.
**v2**: очередь записей офлайн с отправкой при восстановлении соединения.

### Альтернативные LLM-провайдеры
**Сейчас**: один провайдер.
**v2**: плагинная архитектура для смены провайдера без пересборки бэкенда.

## Примечания

- Все пункты валидируются данными реального использования MVP.
- Приоритеты могут измениться по результатам user testing.
- Пункты, отмеченные 🔴, рекомендуется решить в первую очередь — они блокируют целые сегменты пользователей.
